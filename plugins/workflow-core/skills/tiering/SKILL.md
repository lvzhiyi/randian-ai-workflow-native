# 三档分级

按风险与不确定性而非行数定档，完整档条件优先。先说明建议档位、依据、实施范围与验证范围，取得人工确认并记录来源；不能用 Agent 自报代替。用户已明确确认的同一档位和范围直接复用有效证据，不重复询问。

- **轻量**：文案、文档、局部样式、预期明确的局部小 Bug，不新增能力或改变契约。会话/已有 Issue 留目标、范围、验收、来源和至少一项实施 todo；不强制 PRD 或独立计划。
- **标准**：复用架构、边界明确、局部模块的小功能，无权限、安全、迁移或跨系统契约变化。原位 3～5 步短计划与证据；人工定档及范围确认后，无额外方案审批。
- **完整**：跨模块、新架构、鉴权/权限/安全、持久化迁移、破坏性或外部契约变化、关键业务规则不确定，或用户要求提案。复用现有规格工具；方案写目标、范围与非目标、影响、风险/回滚、验收和结构化 todos，另获人工方案批准后实施。无工具时用项目既定记录，不自行初始化。

三档共同路径：任务就绪 → 完整读取适用基线 → 实施 → 规定验证 → Spec + Standards 两轴通过。轻量可压缩记录，不能跳过人工定档、基线、验证或任一评审轴。Agent 终态是“评审通过”，不是自测完成、人工验收或产品交付。

## 授权有效期与变化

- 批准绑定任务当前轮次及控制摘要，有效性看当前范围和证据，不按会话次数或固定时间机械过期。
- 档位、范围、验收或实质方案改变：暂停依赖部分，重新人工确认；完整档重新批准。保留原轮次和证据历史，不把旧授权扩展到新范围。
- 换会话/Agent、原范围修复重试、措辞调整和 todo 细化不新增审批；必要时重读基线、复验，但不重批有效方案。
- 一个变更可关联多张卡，复用变更不等于获准实施全部任务。不为每张卡重复提案。
- Bug 先核对预期、复现与根因。TDD 优先，无法采用时记录原因和替代验证，不增加人工豁免审批。

引擎可能对控制字段保守撤销授权；展示措辞用 `note`，不要为文案调整重写控制字段。真实语义变化与摘要不一致时明确报告，不能假装批准仍有效。CLI 与防护栏边界见 `workflow`。
