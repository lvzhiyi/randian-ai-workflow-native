# 中断与恢复交接

中断指工作没结束就暂停、换会话、上下文将耗尽、换人/换 Agent 或异常退出，不要求出错。受阻问题仍按 `verify` 分类，用同一份任务记录，不维护两套状态。

## 记录位置（以项目配置为准）

- 有规格变更（如 OpenSpec change）：`<变更目录>/handoff.md` 保存当前快照；tasks 仍是唯一完成清单，handoff 只链接任务编号。
- 无变更的跨会话任务：项目配置的交接目录，默认 `docs/development/handoffs/<task-id>.md`，task-id 简短唯一。不为普通 Bug 强行建提案。
- 当次完成的小任务不建交接文件；**未完成且准备换会话时必须写入仓库**，不能只依赖聊天摘要。
- 续做时按用户给的任务/变更查找记录；多个候选对不上先确认，不按修改时间猜。

## 何时保存

1. 开始明确需要跨会话的任务时，建最小记录并标“进行中”。
2. 完成有意义的小步骤、关键决定改变、拿到重要验证结果时更新，特别是长命令启动前。
3. 暂停、交接或会话结束前更新为“已暂停 / 受阻 / 实施完成，待验证”，写第一条可执行的下一步，并告诉用户记录路径。
4. 异常退出无法保证写入；恢复者以 Git 和实际文件重建缺口，不把快照当自动备份。

模板：`${CLAUDE_PLUGIN_ROOT}/templates/handoff.md`。不保存 token、测试账号密码或完整敏感日志；机器上的临时文件不算跨机器交付物。

## 恢复步骤（所有 Agent 接手的唯一步骤来源）

不依赖上一位的聊天记忆、工具会话或本机临时文件；只读授权范围相关材料。

1. 读根目录规范、交接记录、相关规格/设计和任务清单，确认目标与已批准范围。产品任务先从项目首页/总览定位模块卡，再由卡定位需求章节和设计索引。前任的建议或“已读取”不等于批准。
2. 查看当前目录、分支、HEAD、`git status --short`、相关 diff 和必要日志，与快照比对；未提交和未跟踪文件单独确认。对照源码区分目标、已实现、已验证。
3. 检查期间其他人的改动，归属不明时不覆盖；**不为恢复快照自动 reset、clean、stash 或检出覆盖文件**。
4. 检查快照里记录的运行中命令和服务是否真的存在、结果是否已生成；会话 ID 和进程 ID 可能失效，不盲目重复有副作用的操作。
5. 核实 SDK、依赖、接口和设备，重跑最小基线或原失败用例；代码变了的旧“通过”只作参考。缺记录时先调查现状，形成新快照。
6. 简要说明恢复出的状态、本轮可推进范围、所缺条件和最小验证方式，从第一项未完成的工作继续；验收或范围变了，回到需求确认。
7. 结束或中断前，在权威记录里保存决定依据、实际结果、未覆盖项和下一步。

## 收尾

任务真正结束后把快照标为“已结束”，链接实际验证和 PR/交付记录，保留未解决事项。规格变更的交接随变更一起归档。写交接文件不自动授权提交、推送或归档。
