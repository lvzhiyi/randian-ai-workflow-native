# 接口契约与联调

契约来源由项目配置指定（如 Apifox 某项目）。读取时记录接口路径和读取时间；平台未覆盖时引用经前后端确认的接口说明。**样例响应不能替代字段契约**，不凭文档检索工具或猜测补齐内部接口。

## 实施前确认

| 项目 | 内容 |
| --- | --- |
| 请求 | 方法、路径、Header、鉴权、Path/Query/Body、Content-Type；上传字段及大小/类型限制 |
| 字段 | 类型、必填、可空、缺失与空值语义、默认值、枚举、未知枚举处理 |
| 数值和时间 | 金额/数量单位、精度与舍入责任，ID 类型，时间格式与时区；不自行推断 |
| 返回 | HTTP 状态、业务 code、包裹层、成功/失败样例、错误码与用户提示 |
| 列表 | 页码起点、pageSize、排序、筛选编码、总数/hasMore、空页、重复数据 |
| 写操作 | 前置状态、权限、重复提交、幂等、超时后的结果确认；不默认后端支持幂等 |
| 协作 | 前后端/测试负责人或待指定、契约版本、可联调时间、测试环境、阻塞项 |

关键字段、权限或状态流转未确认时，暂停依赖实现；可先做不依赖它的布局或调查。契约记录写在关联规格变更的 design/tasks 或 Issue，只维护一处。

## Mock 与真实联调

| 阶段 | 能说明 | 不能替代 |
| --- | --- | --- |
| Fixture/Mock | 指定输入下的解析、状态与界面行为 | 真实鉴权、实际返回格式、服务端副作用 |
| 真实联调 | 指定环境、账号、数据、版本下的端到端交互 | 未覆盖角色、边界、发布环境 |

1. 明确当前用 Mock 还是真实环境，在交付记录标注，禁止静默切换。
2. Mock 来自已确认契约，覆盖成功、空、业务失败、异常字段和边界。
3. Mock 只放测试或明确的开发入口；生产路径不得“失败就返回成功假数据”。
4. 后端就绪后用同一场景真实联调，核对序列化、鉴权、响应处理、最终页面状态。
5. 发现差异先判定契约、Mock、客户端、后端哪方需调整；不用放宽 DTO 或吞异常掩盖问题。
6. 未联调标记“实施完成，待联调”；除非负责人明确接受分阶段交付，否则不标可合并。

## 测试账号与数据

- 只用明确授权的测试环境和账号；联调前核对 base URL、环境配置、账号归属。
- 账号权限覆盖本次涉及的角色；只有正向账号通过，不能说明越权被阻止。
- 凭据走团队安全渠道，不写入 Markdown、fixture、日志、截图或 Git。
- 优先用合成、可重建、带测试标记的数据；不依赖共享环境里偶然存在的固定 ID。
- 支付、库存、短信、通知、上传等有副作用的操作，先确认测试能力和恢复方式；不得触发真实支付、短信或生产数据写入。
- 清理只限本次测试明确产生的数据。

## 最小场景清单（按功能挑选）

正常、空数据、字段缺失/null、边界值、未知枚举；无权限、登录过期、业务拒绝、服务错误、超时、重试；分页首末页、筛选刷新、重复点击、并发、退出页面后响应；写操作后重新查询确认服务端状态，超时先查结果再决定是否重试。

## 联调记录模板

```text
接口契约：链接、版本/确认时间
负责人：前端、后端、测试（未指定则写明）
运行环境：客户端提交/工作区、后端版本或部署时间、环境别名
数据：账号角色、初始状态、测试数据标记、重建与清理方式（不含凭据）
结果：逐项 Mock 通过 / 真实联调通过 / 失败 / 未验证
证据：请求方式、脱敏响应、requestId/时间、页面结果
差异与阻塞：责任人、待确认事项、恢复条件
清理：已清理 / 按约定保留 / 待负责人处理
```
