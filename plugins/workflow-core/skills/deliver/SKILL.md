# 统一交付结果

所有档位的最终回复都用下面的格式，先给一句结论并写明实际状态。轻量任务每项一句即可，复杂任务按需展开；用户明确要求其他格式时优先遵从，但保留必要证据和限制。不重复输出计划、实施流水账或多份总结。

```text
结论：<本次结果与实际状态，不把代码完成写成产品已验收>
1. 场景：<本次交付的业务/验收场景；文档任务写修正的规则或事实范围>
2. 文件：<本次实际修改的文件及用途；不把已有未提交修改计入本次>
3. 验证：<实际命令/操作、结果及对应版本；未提交时注明 HEAD + 本次工作区>
4. 剩余：<失败、未验证、阻塞及下一步；无则写无，需用户输入时说明具体内容>
5. 同步：<需求卡、技术 tasks、规格、交接分别已更新/无需更新/待更新，附路径或原因；有新增或修改记录时写明“新增记录已按文档最小化检查”>
```

## 要求

- **验证**：明确通过、失败、受阻或未执行；区分自动测试、Mock、真实联调、设备操作、人工验收。对应版本至少标提交或 HEAD + 工作区；复用历史证据注明版本与适用范围，不写成本次重新通过。长日志只引用，不整段粘贴。
- **剩余**：写影响和第一条可执行的下一步；未执行 ≠ 失败。不在默认验证范围的平台简短注明“按当前约定未执行”。
- **同步**：写“新增记录已按文档最小化检查”前，必须逐处对照 `implement` 的文档最小化规则完成检查；没检查不得写这句。只核对本任务相关记录；没有卡/变更或无需交接时写“不适用”，不为凑齐五项新建文件。
- 交付结果默认只写在当前会话，不为每次任务建 `summary.md` 或报告。受阻或中断仍按 `handoff` 维护可恢复记录，最终回复链接它。
- 固定格式是报告约定，不替代按档位要求的检查、评审、验收或提交/发布授权。

## 完成状态口径

| 状态 | 条件 |
| --- | --- |
| 实施完成，待验证 | 修改完成，但必要检查或设备验收仍缺；不能简称“完成” |
| 可评审 | 范围和证据齐全，必要检查通过，或已列出待决阻塞；有阻塞不代表可合并 |
| 可合并 | 相关检查和 CI 通过，评审及业务验收满足；例外由负责人明确接受并记录 |
| 已上线 | 经授权发布，部署结果和必要上线验证已确认；不由本地通过推定 |
| 受阻 | 缺关键条件，记录原因、已做工作和恢复条件 |

提交、合并、发布各自遵守授权边界。
