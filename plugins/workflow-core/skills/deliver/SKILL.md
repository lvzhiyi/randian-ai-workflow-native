# Agent 总结与人工交接

阶段汇报只写结果、证据和真实缺项；授权范围内继续，不机械等“是否继续”。正式总结先写实际状态，格式自由，覆盖本次范围与验收、修改用途、验证与两轴评审、适用版本、未覆盖项/风险、第一条可执行下一步和必要记录同步，不为不适用内容凑五项标题或新建总结文件。

## 总结前核对

1. 按 `workflow` 查询引擎 `status` / `snapshot`，核对任务 ID、当前轮次、尝试、输入快照和有效证据。聊天总结、技能加载、度量和任务卡勾选不替代引擎证据。
2. 所有档位检查 `verify.*` 的每项真实结果、验收覆盖、适用平台与 CI（项目要求时）。代码改动说明格式、静态分析、相关测试；文档说明对应检查。区分通过、失败、未执行/中断、执行异常、失效，不能拿旧成功冒充当前通过。
3. 所有档位说明 Agent Spec + Standards 两轴结论、必修解决情况与证据。未执行任一轴不能写评审通过；流程例外不能伪造成通过。
4. 只同步本任务权威记录，不重复任务清单或写实施流水。原生回调未覆盖的宿主使用人工终端兜底并说明实际支持范围，不把普通流程确认当可信签署或宿主实测。

## 状态口径

- **实施中 / 实施完成，待验证**：todo 或必要检查未完成，不能简称任务完成。
- **验证通过，待评审**：本轮规定验证全部通过，仍待两轴有效报告。
- **评审未通过**：必修未解决、任一轴失败或证据失效；原范围修复后复验重审。
- **评审通过**（`review_passed`）：规定验证全部通过且两轴通过、证据有效；Agent 终态。可附“待人工验收/交付”，不再用“自测完成”作为终态。
- **受阻 / 已暂停 / 已取消**：分别记录真实恢复条件、主动暂停或取消事实。无事件只写“活动未知”，不猜阻塞。

## 人工验收与交付

`deliver` 是 Agent 结果总结和人工交接，不是自动完成产品。单独记录人工验收人与时间、范围/版本、结论、交付去向及来源链接；未发生写未进行。需求卡人工完成勾选只依据实际人工验收/交付确认，不能因 Agent 评审通过、PR 合并或技术 todos 完成而勾选。

人工退回保留原轮次与证据，按 `handoff` / `tiering` 开新轮并重新授权；原范围自动修复重试不额外审批。外部工具同步仅在已有接口和授权范围内进行，本期不宣称已建设集成框架。提交、推送、发布仍需各自授权。

辅助度量命令仍使用宿主会话占位 `--session "${CLAUDE_SESSION_ID}"`（插件根为 `${CLAUDE_PLUGIN_ROOT}`，Codex 前置 `WORKFLOW_HOST=codex`）。先查看实际 `workflow_metric.py --help` 和当前 schema；只有兼容当前真实状态才记录，不能用旧枚举冒充新终态。没有真实会话 ID 不猜填。

统计只作辅助；若历史度量 schema 不支持新终态，说明兼容缺口，不把“评审通过”映射成“自测完成”以凑成功。中断或受阻按 `handoff` 保存可恢复记录；用户限定不新增文件时原位交接。
