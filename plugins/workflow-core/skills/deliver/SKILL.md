# 统一交付结果

下文的 `${CLAUDE_PLUGIN_ROOT}` 指当前技能所在的插件根目录。如果它没有被替换成绝对路径（如在 Codex 中），从已加载的 `SKILL.md` 路径向上三级定位，执行命令时直接代入绝对路径。在 Codex 中运行下方命令时，在命令前加 `WORKFLOW_HOST=codex`，以使用 Codex 的本机数据目录。

## 汇报与正式交付

阶段汇报只写结果、证据和阻塞；没有阻塞不必凑项，不重复计划、实施流水账或完整交付摘要。授权范围内继续推进，不因汇报而等待“是否继续”。

正式交付先说明结果与实际状态，格式自由，可按任务复杂度组织成短文或列表。内容应覆盖本次范围与验收场景、实际改动及用途、验证结果与适用版本、未覆盖项与风险及下一步，以及确有必要的记录同步；不要求固定标题、顺序或五项模板，不为无变化、不适用的内容凑项。用户指定格式时优先遵从，但不省略影响判断的证据与限制。

## 要求

- **验证**：明确通过、失败、受阻或未执行；区分自动测试、Mock、真实联调、设备操作、手动自测。对应版本至少标提交或 HEAD + 工作区；复用历史证据注明版本与适用范围，不写成本次重新通过。长日志只引用，不整段粘贴。
- **代码改动的最低证据**：本次改了源代码时，交付中必须说明格式检查、静态分析、相关测试三项的实际结果（见 `verify`）；缺任何一项时，结论不能写“实施完成”或“可评审”，只能写“实施完成，待验证”并说明缺口及下一步。
- **评审**：标准档、完整档改了代码时，交付前加载 `workflow-core:review`（Claude Code 中调用 Skill 工具），交付中简述评审结论；有未解决的“阻塞”时结论不能写“可评审”或更高；跳过评审时说明原因。
- **剩余**：写影响和第一条可执行的下一步；未执行 ≠ 失败。不在默认验证范围的平台简短注明“按当前约定未执行”。
- **同步**：只核对本任务相关记录，交付前逐处对照 `implement` 的文档最小化规则检查新增记录；需要同步时说明权威位置及实际状态，不要求固定确认句。没有卡/变更或无需交接时可省略，不为报告新建文件。
- 交付结果默认只写在当前会话，不为每次任务建 `summary.md` 或报告。受阻或中断仍按 `handoff` 维护可恢复记录，最终回复链接它。
- 汇报和交付措辞不替代按档位要求的检查、评审、自测或提交/推送授权；技能加载、度量记录也不构成完成证据。可选严格引擎模式见 `workflow`，启用时以引擎状态为权威，不用文字宣告覆盖未满足的门槛。

## 完成状态口径

| 状态 | 条件 |
| --- | --- |
| 实施完成，待验证 | 修改完成，但必要检查或设备自测仍缺；不能简称“完成” |
| 可评审 | 范围和证据齐全，必要检查通过，标准/完整档代码改动已评审且无未解决的评审阻塞；有未解决阻塞时不能标为可评审 |
| 自测完成 | 开发工作流的终态：验收场景已逐项自测并留证据（依据任务卡或规格；没有卡和规格时，如轻量档，对照当前会话确认的预期），相关检查通过；项目有 CI 且覆盖本次改动时 CI 也须通过，不进 CI 的部分以本机验证结果为准；标准/完整档评审无未解决阻塞；未覆盖项由用户明确接受并记录 |
| 受阻 | 缺关键条件，记录原因、已做工作和恢复条件 |

测试阶段、产品验收和上线属于其他阶段或部门，不在本工作流的状态内，也不作为自测完成的前置条件。提交、推送、合并各自遵守授权边界。

## 记录度量

任务结束或阶段性停下、写最终回复前，写一条度量记录，所有档位都要。`status` 与结论一致；`unverified` 按 `verify` 的分类写未验证的原因，默认范围外的平台写“按约定未执行”；`resolutions` 写本次评审问题的去向，`rule` 与评审记录一致；`review` 按实际写“已评审 / 已跳过 / 不要求”。只写这些字段，不写代码、命令或日志。

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/scripts/workflow_metric.py" record deliver --session "${CLAUDE_SESSION_ID}" <<'JSON'
{"task": "<任务编号或分支>", "tier": "轻量|标准|完整", "status": "实施完成，待验证|可评审|自测完成|受阻", "code_changed": true, "review": "已评审|已跳过|不要求", "unverified": [], "resolutions": [{"rule": "<依据>", "outcome": "已修复|接受例外|未解决"}]}
JSON
```

记录失败时按输出修正一次，仍失败就说明记录限制；度量不替代验证证据，也不能改变实际完成状态。
