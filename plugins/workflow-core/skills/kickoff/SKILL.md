# 开工准备

## 开始任务

1. 读项目 `AGENTS.md` / `CLAUDE.md` 及本任务适用的规范；检查分支、HEAD、`git status`、相关 diff，保护已有修改和未跟踪文件。
2. 找到相关代码、需求/规格、进行中变更，明确范围、验收和依赖证据。已有任务卡则核对权威 PRD 版本；小任务不强制导入 PRD。
3. 用一句话说明档位判断与最小验证计划（见 `tiering`），按对应路径执行。缺少关键条件先调查，不机械重复索要已有批准。
4. 范围变化按升级规则处理，关键决定写回已有任务记录。

只读本任务涉及的规范、PRD 章节、卡和源码；续做只补读变化内容和必要交接，不反复全库读取。

## 准备检查（按任务规模做最小检查，结果留在会话或 Issue/变更里）

- **范围**：目标、非目标、验收条件、必要审批是否明确。
- **工作区**：当前分支、用户已有修改、相关进行中变更是否冲突。
- **环境**：SDK/依赖、设备、接口契约、测试账号和数据是否足够；不把真实凭据写入记录。
- **基线**：纯文档跑项目配置的文档检查；代码任务先跑相关测试和必要分析，记录已有失败；范围大时跑完整检查。命令取自项目配置和技术栈插件。
- **UI 与设计**：涉及页面时核对设计文件/页面/节点、主稿与素材、共享 UI 与业务范围、缺失状态与差异；只读到结构或文字时不声明视觉已核对。
- **接口与数据**：涉及后端时确认契约版本、负责人、Mock/真实阶段、可重建测试数据（见 `api-contract`）；缺关键契约不猜。
- **验证计划**：说明将执行的检查及必须人工验证的操作。已有失败不自动豁免新回归。

信息缺失时先完成不依赖它的调查；缺关键业务契约、必要批准或安全测试条件时，**不猜测、不继续依赖它的实现**。

## 平台验证范围

默认验证哪些平台由项目配置决定（如“默认只验证 Android，iOS 仅在明确要求时执行”）。未在范围内的平台写“按当前约定未执行”，不记为失败或通过。项目没写时，验证本机能跑的主平台，并在交付中注明未覆盖平台。
