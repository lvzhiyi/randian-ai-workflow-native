# 任务就绪检查

1. 读取项目入口与 `ai-workflow.yaml`；检查分支、HEAD、`git status`、相关 diff，保护并行修改和未跟踪文件。定位任务 ID，查询引擎 `status` / `snapshot`，不以文档勾选代替状态。
2. 核对目标、范围/非目标、验收、需求来源及依赖完成事实；缺字段明确列 missing。来源链接未读不算核对，空依赖列表只表示确认无依赖。
3. 按 `tiering` 核对三档人工定档和范围确认；标准短计划不额外审批，完整方案另获批准。既有有效授权不重复索要。
4. 检查环境、设计、接口、数据及验证条件，列出可执行检查和人工操作。缺项只允许调查或独立且已就绪的其他任务，当前未就绪任务不可进入实施。
5. 成功完整读取配置中适用的必读基线，并记录路径、内容版本/摘要、读取字节与覆盖范围、执行者和轮次。缺失、失败、截断、冲突未处理不能通过；引用只按适用范围展开，不无限递归。CLI `read-baseline` 在限额内返回 `document.content` 正文并登记完整读取；超限或截断不登记完整。Agent 必须实际使用正文，不能把回执当理解证明。
6. 就绪后通过引擎 `start` 进入实施；命令与参数先看实际 CLI `--help`，通用入口见 `workflow`。

## 检查要点

- **文档基线与执行基线分开**：前者是必读规范，后者是修改前测试/分析结果。文档改动先跑相关文档检查；代码任务先跑相关测试和分析，记录既有失败及同环境证据。
- **UI/设计**：核对主稿、页面/节点、状态、素材、共享 UI；仅文字/结构已读不能声明视觉已核对。
- **接口/数据**：核对契约版本、负责人、Mock/真实联调阶段、可重建测试数据；关键契约不明不猜，见 `api-contract`。
- **平台**：按 `platforms.*`，范围外写“按约定未执行”；未配置时先确认可验证主平台，不凭空许诺全平台通过。
- **恢复**：新 Agent 必须重读适用基线，旧 Agent 在内容变化时重读；有效方案不因换执行者重批。核对任务、当前轮次和活动主执行者，运行中命令先查真实进程；未知活动不猜阻塞。

不在当前任务中途自行补配置或降低要求；缺关键批准、基线或安全测试条件时报告影响与恢复条件。
