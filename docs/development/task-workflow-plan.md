# 任务级工作流实施计划

## 已批准范围

面向 Claude Code 与 Codex，以任务为单位控制与观测流程。需求接收并入需求拆解；Dashboard 只读，不展示全局八步或独立阻塞区，Trace 并入执行观测。保留 handoff。

采用始终启用的插件级流程门禁：引擎统一规则与状态，宿主执行受支持工具路径的拦截。不提供提醒/严格模式或引擎开关。用户已确认本期不建设可信审批服务，不承诺抗程序代答、同账号防篡改或完整写入路径覆盖。审批以原生用户确认的流程证据记录，不将 TTY 或普通状态更新当作可信签署。宿主能力不足明确报告，不能静默降级。

## 任务与授权

- 任务就绪检查涵盖目标、范围、验收、来源、依赖与缺项；未就绪可以调查，不可实施。
- 数据关系为任务、执行轮次、阶段尝试、版本绑定证据。续做复用有效轮次；重试新增尝试；返工、实质范围变化保留历史并重新授权。
- 三档都人工确认档位及实施范围。轻量保留简要记录；标准有原位短计划、不额外审批；完整有方案、目标、影响/非目标、风险/回滚、验收与 todos，并额外审批。
- 换会话/Agent、原范围修复、todo细化、措辞调整不重新审批；档位、验收、范围和实质方案改变须重新确认。摘要检测差异，但不能将每个字节变化都等同实质变化。
- 每轮主执行者明确，子 Agent 继承绑定授权，更新采用版本检查，取消不可自动恢复。

## 实施、验证与评审

- 必须成功完整读取配置中适用基线，记录版本、覆盖范围和执行者；失败/截断不能通过。必读缺失暂停，冲突需处理，不无限递归引用。新 Agent 重读但不重批有效方案。
- TDD 优先不强制。不采用时按任务/步骤记录原因与替代验证，不增加人工豁免审批。
- 实施 todos 结构化记录；步骤完成不等于验证通过。
- 沿用 verify.light/standard/full 和平台配置，逐项真实执行；遗漏不能通过。阶段明细区分失败、未完成/中断、执行异常、证据失效及恢复动作，主状态保持简洁。
- 原范围可自动修复重试，不得删断言或降低检查要求；没有新证据/假设时停止无效重试。相关输入改变使下游证据失效。
- 本期仅 Agent 的 Spec + Standards 双轴评审，规定验证全部通过且两轴通过后才为评审通过。评审通过是 Agent 终态，非人工验收或无缺陷证明。
- 人工验收/交付独立记录，预留内部工具同步接口，不建设外部集成框架。

## 观测与恢复

卡片展示档位、主状态、阶段说明、局部流程、todo进度、失败/阻塞/待确认、有效证据和下一步。详情展示批准版本、基线读取、验证清单、评审与轮次历史。Trace 必须关联项目/任务/会话/轮次，未归属事件不改变状态。

业务阶段和活动状态分离，展示执行者、会话、最后活动和数据新鲜度。没有事件不直接等于阻塞/失联；无宿主退出或心跳证据时只显示活动未知。handoff 保存任务/轮次/尝试、有效证据、失败、待办及恢复条件。

## 实施顺序与验收

1. 控制闭环：双宿主能力核查、模型协议、CLI三档闭环、原生确认与基线门禁。
2. 可观测闭环：只读任务卡、Trace整合、中断恢复、多会话隔离。
3. 迁移交接：配置及旧开关迁移、技能模板口径、旧证据标记历史未核验、人工验收接口。

关键验证包括缺批准/基线拒绝、完整档批准、三档评审终态、失败重试和证据失效、取消/轮次/CAS、只读查询无副作用、任务隔离、门禁异常和数据读取限额。先定向测试，再运行项目 python3 scripts/check.py。所有新增或修改注释使用简体中文。不自动提交、推送、发布，不覆盖已有未跟踪 Dashboard 文件。

## 实施验证记录

已实现 v2 轮次/尝试/证据、三档确认与完整方案批准、基线完整正文回执、TDD 替代验证、同轮修复与步骤细化、配置验证命令强制覆盖、双轴 Agent 终态。宿主加入同步门禁、Codex cmd/数组适配、会话持久查找、Claude 请求版本绑定确认；Codex 原生确认仍以人工终端兜底。CLI 内联 JSON 消除开工前输入文件死锁。

基线限制 1 MiB，诊断按流限额并脱敏，runner deadline 覆盖排空。已接入项目统一采集 Trace，会话绑定只读归属；无匹配保留未归属。自动化通过不替代真实宿主或浏览器实测；Dashboard 旧开关依赖、普通问答误拦、终态会话歧义和 verify.docs 遗漏已修复并完成定向复核，指定残留的 Spec/Standards 均通过。全项目 266 项通过，后续 Trace SQL 载荷限制的 24 项定向测试通过。尚未做真实浏览器、Claude Code/Codex 会话端到端和人工验收，不将自动化通过等同这些验收。未提交、推送或发布。
