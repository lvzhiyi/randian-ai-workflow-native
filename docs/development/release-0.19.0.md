# workflow-core 0.19.0 — 可读任务看板与 Agent 进度

## 变化

- 改造暗色搜索筛选栏：编号与标题搜索、状态和档位交集筛选、清空、匹配数量及响应式空态。
- 区分当前阻止条件和正常后续阶段，实施期间尚未验证或评审不再笼统作为开工缺项。
- 基线读取、批准、验证诊断、双轴评审和轮次历史改为可读业务摘要；内部标识、绑定与原始技术记录默认折叠，日志按需展开且限额。
- 保留默认可见待确认和完整实施清单，目标、范围、验收、方案、检查计划和交接使用独立业务详情，不要求用户阅读 JSON。
- 新增只读 progress CLI，按当前轮次生成稳定 ID 和步骤状态，失败、失效及暂停不伪造进行中，实施完成不等同评审通过或交付。
- 更新实施、验证、评审与恢复技能，在语义节点由 Agent 同步实际可用原生任务列表；原生展示工具不作为引擎授权或通过证据。

## 能力边界与升级

CLI 只提供进度投影，不是自动 UI bridge。Agent 必须发现真实工具及 schema 后才同步；单项/空清单、不清楚已有计划、无法清理旧轮次或工具拒绝时使用聊天清单，不凑假 todo、不覆盖未知计划、不虚报原生同步成功。

本版不改变引擎的批准、验证与评审通过条件。更新插件后新建会话；正在运行的 Dashboard 服务需重启才能加载新页面代码。

## 验证

发布前执行 python3 scripts/check.py（316 项测试）和 git diff --check。自动化包括 JavaScript 语法、真实过滤函数、轻量 DOM 业务渲染、进度 CLI 与引擎回归。

尚未执行真实浏览器视觉验收及三宿主原生 todos UI 端到端测试。插件仍是流程防护栏，不提供可信签署、抗程序代答或完整写入路径覆盖。
