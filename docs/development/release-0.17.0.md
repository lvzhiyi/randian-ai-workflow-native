# workflow-core 0.17.0

## 变化

- 工作流以任务为中心：需求接收并入需求拆解，任务就绪检查后人工确认三档及实施范围，完整档额外审批方案。
- 引擎协议 v2 引入执行轮次、阶段尝试、版本绑定证据、同轮修复和步骤细化；规定验证与 Agent Spec/Standards 双轴评审通过后交人工验收。
- 插件级门禁始终启用，旧 engine.enabled 不再控制执行；配置基线完整读取和验证命令覆盖纳入检查。
- Dashboard 改为只读任务卡与阶段明细，整合 Trace 执行观测；阻塞、待确认和失败回到任务内部，保留 handoff。
- 增加 CLI 内联 JSON、持久会话绑定、有界诊断、基线大小限制和检查进程排空超时。

## 升级注意

- 行为存在兼容变化：不再提供提醒/严格模式或引擎开关。已接入项目统一执行受支持工具路径的门禁。
- 旧任务需要显式 adopt-protocol；旧批准、验证和评审记录不自动变成 v2 有效证据。
- 核对 baseline.required/scoped 和 verify.light/standard/full/docs；配置的检查必须纳入计划。平台构建命令由项目明确写入各档 verify，引擎不猜测。
- Claude 支持版本绑定的原生确认流程回调；Codex 暂使用人工交互终端确认兜底。
- Trace 整合到 Dashboard；已接入项目采集本机执行事件，日志包含经限额和尽力脱敏的工具摘要，请按项目数据规范管理。

## 验证与限制

发布前运行 python3 scripts/check.py 和 git diff --check。已有自动化覆盖引擎、模拟宿主回调、真实 CLI 集成、只读看板和资源边界；不以这些结果代替真实宿主及浏览器端到端验收。

本版本仍为 0.x 迭代版本。插件门禁是流程防护栏，不是安全沙箱，不提供可信签署、抗程序代答、同账号防篡改或完整写入路径覆盖。真实 Claude Code/Codex 会话、浏览器交互和人工验收尚未完成。Agent 评审通过不等于产品交付。
